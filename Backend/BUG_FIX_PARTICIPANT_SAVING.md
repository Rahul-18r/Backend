# 🐛 Bug Fixes - Participant Not Saving Issue

## Issues Identified & Fixed

### 🔴 **Problem 1: "Remaining slots: -22"**
**Root Cause:** The webhook was checking `remainingSlots` calculation incorrectly. For new participants with 0 existing registrations, the logic was broken.

**Old Logic:**
```javascript
const remainingSlots = MAX_EVENTS - currentValidRegistrations;
if (remainingSlots <= 0) { // This would be 4 for new users!
  return error; 
}

// Then in loop:
if (newRegistrations.length >= remainingSlots) break; // This would never break correctly
```

**The Problem:**
- New participant: `currentValidRegistrations = 0`
- `remainingSlots = 4 - 0 = 4`
- Trying to add 2 events: Should work!
- But the loop was breaking incorrectly
- The "remaining slots: -22" suggests the array was somehow corrupted or the calculation was wrong

---

### 🔴 **Problem 2: Participant Not Saved to Database**
**Root Cause:** New participant was created but `participant.save()` was only called after adding registrations. If ticket generation failed, the participant was never saved.

**Old Code:**
```javascript
if (!participant) {
  participant = new Participant({...}); // Created but NOT saved
}

// Later...
const ticketUrl = await generateTicket(
  participant._id.toString(), // ❌ participant._id is undefined!
  ...
);

// Only saved here:
if (newRegistrations.length > 0) {
  participant.registrations.push(...newRegistrations);
  await participant.save({ session }); // Too late!
}
```

**The Problem:**
- New participant created but not saved
- `participant._id` is `undefined` until saved
- `participant.ticketUid` is also `undefined` until saved
- Ticket generation uses `participant._id` → fails
- Transaction aborts → participant never saved

## ✅ Fixes Applied

### Fix 1: Save Participant Immediately After Creation

**New Code:**
```javascript
if (isNewParticipant) {
  participant = new Participant({
    name,
    usn,
    phone,
    college,
    registrations: [],
  });
  console.log(`Creating new participant for phone: ${phone}`);
  // ✅ Save immediately to generate _id and ticketUid
  await participant.save({ session });
  console.log(`New participant saved with ticketUid: ${participant.ticketUid}`);
}
```

**Benefits:**
- ✅ `participant._id` is now available
- ✅ `participant.ticketUid` is auto-generated by Mongoose
- ✅ Ticket generation can use these values
- ✅ Even if ticket generation fails, participant exists in DB

---

### Fix 2: Better Event Limit Validation

**New Code:**
```javascript
// Check if the new registrations would exceed the limit
if (currentValidRegistrations + registrations.length > MAX_EVENTS) {
  console.warn(`Cannot add ${registrations.length} events. Only ${remainingSlots} slots available`);
  await session.abortTransaction();
  return res.status(400).json({ 
    success: false, 
    message: `Cannot register for ${registrations.length} events. Only ${remainingSlots} slot(s) available. Maximum ${MAX_EVENTS} events allowed.`
  });
}
```

**Benefits:**
- ✅ Clear validation before processing
- ✅ Aborts transaction properly
- ✅ Better error message
- ✅ No partial processing

---

### Fix 3: Removed Breaking Loop Logic

**Old Code:**
```javascript
for (const event of registrations) {
  if (newRegistrations.length >= remainingSlots) break; // ❌ Wrong logic
  ...
}
```

**New Code:**
```javascript
// Validation happens BEFORE the loop
if (currentValidRegistrations + registrations.length > MAX_EVENTS) {
  return error;
}

// Loop processes all valid events
for (const event of registrations) {
  // No break based on remainingSlots
  ...
}
```

**Benefits:**
- ✅ Validates total before processing
- ✅ Processes all requested events or rejects all
- ✅ No partial failures
- ✅ Cleaner logic

## 🎯 What Was Wrong Before

### The Flow Was:
```
1. Create participant object (not saved)
2. Try to generate ticket with participant._id (undefined!)
3. Ticket generation fails OR uses undefined ID
4. Try to save participant with registrations
5. Transaction fails because ticket generation failed
6. Participant never saved to DB
7. ❌ Result: "Participant not found" error
```

### The Flow Now:
```
1. Create participant object
2. ✅ Save participant immediately (generates _id and ticketUid)
3. Generate ticket with valid ticketUid
4. Add registrations to participant
5. Save participant again with registrations
6. Commit transaction
7. ✅ Result: Participant exists in DB with valid ticket
```
